# CLAUDE.md

Guidance for Claude Code working in this repo. Read once at session start.

## Project

**NOMAD** — personal finance tracker (expenses, income, transfers, recurring bills, splits) with an optional daily-routine sub-app. React 19 + Vite SPA on Vercel, backed by **the user's own Supabase project** (BYODB — no central data store). Single-user personal app; not multi-tenant.

## Tech stack

- **Frontend:** React 19, Vite, Recharts, `@phosphor-icons/react` + `@tabler/icons-react`
- **Backend:** TypeScript Vercel serverless functions (`api/`), CommonJS (`api/package.json` is `type: commonjs`; root is `type: module` — don't mix)
- **DB:** Supabase (Postgres), user-hosted, creds in localStorage. RLS is disabled on every table by design — the anon key is the per-user auth boundary.
- **Receipts:** Cloudinary (or local data-URL fallback). **Email reports:** nodemailer + Gmail. **AI:** Gemini → Groq → NVIDIA waterfall.
- **Dates:** date-fns + local helpers.

## Working agreements

- **Never push to `main`** — the user merges PRs. Local sessions: don't `git push` at all (the user pushes from VS Code). Remote/cloud Claude sessions: push only to the session's designated `claude/*` branch (user-granted).
- `App.jsx` and `Routine.jsx` are written **one JSX block per line**. When editing, match a unique substring — do **not** reformat or the build breaks.
- `dist/` is gitignored but historically tracked. After `npm run build`, run `git checkout HEAD -- dist/` before staging; Vercel rebuilds on push.
- On Windows, use the **PowerShell tool** for shell, not Bash-with-PS-cmdlets.

## Architecture

### Credentials / data flow
First run shows `CredentialSetup.jsx`. Creds (Supabase URL + anon key, optional Cloudinary) save to localStorage `nomad-credentials` via `credentials.js`. `App.jsx` reads them at module load; localStorage beats `VITE_SUPABASE_*` env vars.

**Local-only mode is the real onboarding:** new users land straight in the app with data in localStorage (`localMode = !creds.sbUrl`, `needsSetup = false` at top of `App.jsx`). A dismissible amber banner nags them to add Supabase for cloud sync + AI. There is **no demo/sample-data mode** — don't build one.

### Frontend (`src/`)
- **`App.jsx`** — one large component (~3k+ lines) owning all finance state and every view, plus inline helpers (`sbGet`/`sbWrite`/`sbUpsert`/`sbDelete`, date utils, SVG icons). Intentional monolith — don't split without a clear need.
- **`Routine.jsx`** — self-contained daily food/skin/habit/sleep/mood/water sub-app (own tab).
- **AI features live INLINE in `App.jsx`** (there is no `AIHub.jsx` — an earlier version of this doc invented one). Voice add, the statement chat (reconcile against bank/UPI exports), the AI narrative card, and category suggestions all call `POST /api/ai-analyze` with a `mode` param; PII is redacted via `redactTransactions()`/`redact()` before sending.
- **Ask NOMAD answers from a DETERMINISTIC query, not from the model's arithmetic.** `sendChat` (App.jsx) first posts the question to `/api/ai-analyze` mode `chat-query`, which returns only a **query spec** (keywords / category / wallet / amount bounds / date window / groupBy). `src/chatQuery.js` then runs that spec over the **complete local ledger** — every row, no 500-row cap — and computes the total, count, average, min/max, span and breakdown. Those figures go to `/api/ai-chat` as fixed facts under `context.queryFacts`, which switches the endpoint to `GROUNDED_SYSTEM_PROMPT`: phrase these numbers, list only these rows, never recompute. Keyword matching is **whole-word** with a small singular/plural fold (so "eggs" finds `Eggs+tray` and `rice+eggs` but not `Veggies`), and digits count as word boundaries so `Rice5kgs` still matches "rice". Unknown category/wallet/source names are dropped by BOTH sanitizers (server `sanitize("chat-query")` and client `sanitizeQuerySpec`) — a hallucinated filter would return zero rows and read as "you never spent on that". Any failure (no AI, `needsData: false`, a spec with no filter at all per `isEmptySpec`) falls back to the original raw-row-dump path, so the chat degrades instead of breaking. **Don't move the arithmetic back into the prompt** — that's the bug this replaced ("how much on eggs" answered with the whole Food & Drinks category and a total matching none of the rows it listed).
- **`IOUWallet.jsx`** — 1:1 IOU card wallet (Add tab → "IOU · Splits" segment). Neumorphic design with its own local atoms (MINT/CORAL/etc). Quick-add "morph" popup animates `transform` + `opacity` only (GPU) — don't reintroduce top/left/width/height animation. **The opacity leg is load-bearing:** with transform alone, closing shrank a fully-opaque `SURF` panel onto the "New IOU" button and parked it there for the whole animation — a blank pale plate exactly where the button should be, which read as the button breaking. The big `NEU_RAISED` shadow is also dropped the instant a close starts (scaling it non-uniformly smears it and is the most expensive part of the frame), durations are asymmetric (`MORPH_IN` 300ms / `MORPH_OUT` 200ms — the old 380ms both ways is what felt laggy), and `close()`'s unmount timeout reads the SAME constant, so it can't drift from the CSS. `prefers-reduced-motion` skips the transform entirely. `PersonCard` is `memo()`'d against a `useMemo`'d card list + `useCallback` handlers, and the home roster/totals live inside the one `model` memo — App re-renders on every 60s background pull and every toast, and re-walking every person on each of those was the scroll jank. Guarded by e2e `17-people-search.spec.js`. Person rename/merge: pencil in person view → `onRenamePerson(from, to)` (implemented in App.jsx: renames all matching splits + `sbUpsert`); renaming onto an existing person's name merges them. New-IOU name field is a ranked typeahead over `peopleFromSplits(splits)` — EVERY person you've had an IOU with, not the wallet's visible roster (someone whose IOUs all sat in a completed event was unsuggestable, so you'd retype the name and fork a duplicate). Chips WRAP; the old `overflow-x` strip showed ~3 of the matches with no hint the rest existed. Capped at 4 until you type (the morph card is a fixed height — 8 chips pushed "Add IOU" below the fold). **Net settle can be partial AND final:** entering less than the net pays down the net-direction IOUs (general before event), and the sheet's "Write off the remaining ₹X" toggle passes `opts.forgiveRemainder` to `settleNet`/`settleEventNet`, which marks every still-outstanding in-scope IOU `settled + skipped` so the remainder lands in the write-off ledger and the person is actually closed. Without it the tail stays pending (the original behaviour). Fully-paid IOUs are marked `settled` only — never `skipped` — so they don't read as write-offs. Guarded by `netSettle.test.js` + e2e `14-net-settle-writeoff.spec.js`.
- **`CatDonut.jsx`** — the category-spend donut, extracted so recharts lives in a lazy chunk.
- **`CalendarView.jsx`** — month-grid calendar rendered inside the history tab. Shows per-day expense/income totals with a heat-map background (green → yellow → red). Supports controlled selection (`selectedDay` + `onDayClick` props) or internal state; `compact` prop hides the day-detail panel. Props: `expenses`, `incomes`, `refunds` (received IOU repayments — netted off the SPENT header so it matches the hero's Out), `transfers`, `categories`, `wallets`, `onTxClick`, `compact`, `selectedDay`, `onDayClick`, `viewMonth` + `onMonthChange` (two-way sync with the history month chips).
- **`NomadLite.jsx`** + **`nomadLiteSplit.js`** — "NOMAD Lite": a presets shell of standalone quick-calculators launched from the **clock icon in the Events list header** (Events `view === "lite"`). First preset "Current Split" = electricity/utility bill splitter (base load + appliance %-groups + auto/manual extra, donut, cards/table, copy/WhatsApp/print). **localStorage-only** (`nomad-lite-v1`), never synced to Supabase. Theme is global (inherits app CSS vars — no local toggle). Pure split math + helpers live in `nomadLiteSplit.js` so `NomadLite.jsx` stays components-only (`react-refresh/only-export-components` is an error outside App/Routine). Add future presets to the `PRESETS` array.
- **`CredentialSetup.jsx`**, **`ReceiptPicker.jsx`** (image + PDF).
- **Code-splitting:** `Routine`, `NomadLite`, `IOUWallet`, `CalendarView`, `CredentialSetup`, `CatDonut` are `lazy()`-loaded via the `lazyView` helper at the top of `App.jsx` (pre-wrapped in Suspense so call sites stay unchanged; failed chunk fetch renders a reconnect hint). All chunks are idle-prefetched after first paint — **required for offline**, since the SW can only serve what has been fetched once.
- **Boot splash:** `index.html` carries a pure-CSS animated splash inside `#root` (wiped when React mounts) + a pre-paint theme sniff of `nomad-v5`'s `"darkMode"`. Keep it dependency-free.
- **PWA shortcut:** manifest `shortcuts` → `/?add=1`; `App.jsx` reads the flag for the initial tab, then strips it from the URL.
- **Smart Add defaults:** `suggestAddDefaults` (financeUtils) pre-picks category/wallet from recent history; AddPage adopts a late suggestion only while the field still holds its auto value (draft/chip/voice/user changes hand off permanently).
- **"Split with friends" is ONE search-or-create field**, not a chip wall plus an add box. `splitNew` doubles as the query over `splitPeopleList` (`peopleFromSplits(sp)` in App — uncapped and recency-ordered; the old inline `[...new Set(sp.map(...))].slice(0, 12)` was insertion-ordered, kept suggesting people whose only IOU was deleted, and made person #13 unreachable) and as the new-name draft. Chosen people are removable pills above the field (with the per-head share on the "You" pill), suggestions are ranked with the matched run bolded, and already-chosen names are `exclude`d. The create chip needs 2+ characters and renders LAST — mid-typing an existing person is the likelier target, and a primary-styled chip in the first slot invites the mis-tap that forks a duplicate. Enter takes the top hit when what you typed is a prefix of it, else creates the literal text.
- **A settle must move EXACTLY the cash its confirm button promised.** A net settle records one settlement per IOU and leans on the opposite-direction rows to cancel the gross, so the wallet lands on the net only while the sheet and the handler are netting the SAME IOU set — and they derive it independently (`NetSheet`'s `g.net` / `personMap[cur].net` vs `settleNet`/`settleEventNet`'s own `items` scope). Any drift banks the difference silently: History credits a bank with the GROSS of every "owes you" IOU while only the net ever arrived. The sheet now passes `expectCash` (its button's figure, signed by the net's direction) and both handlers refuse to write anything when `cashMatchesExpectation(opts.expectCash, settlementsCash(recs))` fails. `settlementsCash` (financeUtils) is the single answer to "what did this batch do to the wallet" — it reads `amount` in FULL (an overpay really does leave the wallet), unlike `settlementNetAmount` which nets off `excess` for the split ledger. Don't add a settle path that skips the check. Guarded by `settleCash.test.js`.
- **History groups settlements by person + day + WALLET, never by direction.** With direction in the key a net settle filed as two unrelated cards ("Rakesh paid back ₹74.50" beside "Paid Rakesh ₹32.50"), so reconciling History against a bank statement read the gross as money that had landed. One card carries the net (`__netted` → "Settled with X · NET"), expandable to the legs.
- **Never filter a Supabase DELETE on anything but `id`.** PostgREST matches column names EXACTLY and ours are camelCase (`"groupId"`, `"eventId"`, `"splitId"`), but the bulk deletes were written `group_id=eq.…` / `event_id=eq.…` — Postgres answered 400 and the rows were never deleted server-side, so the 60s background pull handed them straight back. Resurrected settlements put cash into a wallet with no transaction left to explain it. Every cleanup now loops `sbDelete` (soft) / `sbDeleteRow` (hard) per id; `id` is spelled the same in both conventions, and the id-shaped dedupeKey is also what lets `mergeRemote`'s `isPendingDelete` shield the row from a racing pull. `sbDeleteWhere` survives only as `sbDelete`'s 400 fallback.
- **Deleting an IOU deletes its settlements too** (`delItem(id, "split")`), and Undo restores both. A settlement is the record of cash that moved; orphaning it leaves that money in the wallet with nothing on any screen to trace it back to.
- **Quick add is ONE TAP LOGS IT, in a single compact rail.** A pattern only appears here after being logged twice or more in 60 days, so its amount, category, wallet and note are all settled — there is nothing left to decide, and the old behaviour (fill the form, then scroll past the amount hero to a save button) *was* the whole cost of logging it. Tap writes the expense through `quickLog` → `addE(…, { silent: true })`, so every balance check, UPI-Lite cap and budget alert still fires; only the confirmation toast changes, to one carrying **Undo** (`undoDelete` buffer type `"unadd"`) — a tap that spends money has to be reversible in the same gesture. **Hold (420ms) fills the form instead**, for the times you want to tweak first; `qaHold.held` swallows the click that follows the release or a hold would do both. The pills are ~34px, WRAP (never `overflow-x` — a hidden scroller sliced the last one off at the viewport edge), and are ordered so a category's patterns sit adjacent, each carrying that category's colour + icon. Frequency is the bar along the pill's bottom edge (width = share of the most-logged pattern), which costs no height. **Per-category shelves were tried and reverted**: they grouped correctly but spent ~570px of scroll to save typing, which is backwards for the one screen whose entire job is speed. Guarded by e2e `17-people-search.spec.js`.

### Offline-first write path
All Supabase writes go through `sendSupabaseRequest` in `offlineSync.js`. Offline or 5xx → serialised into localStorage queue `nomad-sync-queue-v1`, replayed on reconnect/visibility. Dedup by `dedupeKey`; bodies merged on dedup. Per-item retry; after 3 fails → dead-letter `nomad-sync-failed-v1`. Drops surface via `subscribeSyncDrops` (wired to toasts) — route any new drop condition through it. In production, writes route through **`/api/sync`** proxy for server-side idempotency (`nomad_sync_keys` table); dev/test go direct.

### Cross-device live pull
An open tab fetches Supabase only once on mount, so a row added on another device used to stay invisible until a full reload ("new entries missing on other device"). `App.jsx` runs a **background re-pull** — `load({ skipLocal: true })` on tab refocus (`visibilitychange`) **and** a 60s interval — via a `loadRef` so the interval always uses the latest closure. `load()` flushes the offline write queue first (push), then re-fetches + `mergeRemote` (pull); `mergeRemote` keeps any pending-upsert local row so a background pull can't clobber an in-flight edit. **`skipLocal` is load-bearing:** under `if (!skipLocal)`, the mount load restores local-only prefs (theme, categories, income sources) from the `nomad-v5` backup — background pulls MUST skip that, or a pull firing inside the 800ms backup debounce reverts a just-added category / theme toggle.

### Soft delete & conflicts
`sbDelete` is a soft delete (PATCH `deleted_at=now()`); `sbDeleteWhere` is a hard DELETE (bulk/nuke). `sbGet` appends `&deleted_at=is.null` only for `SOFT_DELETE_TABLES` = {expenses, incomes, transfers, recurring, events, splits}. Optimistic concurrency: recurring edits send `If-Unmodified-Since` from version cache `nomad-record-versions-v1`; 412 → conflict toast + discard; flush strips the header so offline replays always win. Recurring is the only table with conflict detection (the others are append-only).

### Local backup & PWA
Full state mirrored to localStorage `nomad-v5` (loaded as fallback). Categories/incomeSources/autoRules/budgets/savings-goals optionally sync cross-device via the **`user_prefs`** JSONB table (single row keyed `"nomad"`, dedupeKey `user_prefs:nomad`) — `load()` probes it once: present → `prefsSync="on"` (a debounced effect pushes `{categories, incomeSources, autoRules, budgets, goals}`, and remote is adopted when present & not pending a local upsert); absent (un-migrated) → `prefsSync="off"`, stay localStorage-only with **zero error toasts**. Adoption asymmetry is deliberate: categories/incomeSources only adopt a **non-empty** remote list, but budgets (`{}` ok) and goals (`[]` ok) adopt empty values too, so "clear all budgets" / "delete last goal" propagates — only a prefs row that predates those keys leaves local state alone (and the baseline mismatch then re-uploads local, migrating the row). Budgets/goals also keep their own localStorage keys (`nomad-budgets`, `nomad-goals-v1`) so they work offline/local-only; goal contributions are manual markers and **never touch wallet balances** (`goalProgress` in financeUtils is the single render source — dashboard card + settings editor + e2e `13-savings-goals.spec.js`). So these still work offline/un-migrated, and follow you across devices once `nomad_setup.sql` is re-run. `nomad-v5` remains the local fallback + backup-export source. `public/sw.js`: navigations serve the cached shell INSTANTLY and refresh it in the background (this is what makes cold opens fast — don't revert to network-first); hashed assets are cache-first; skips Supabase + non-OK/opaque responses (and ignores all non-GET, so the ntfy POST passes through); bump `CACHE_NAME` when changing it (Vite plugin auto-injects a build-version suffix). Deploys reach users via the "App updated — reload" banner (new SW waits for SKIP_WAITING; see `main.jsx`).

### Notification centre
Bell in the dashboard header (unread badge) → full-screen sheet listing what still needs attention: bills due/upcoming, outstanding IOUs, budget breaches, sync failures. Backed by **localStorage only** (`nomad-notifications-v1` via `src/notifications.js`) — never synced to Supabase, since every entry is derived from data that already syncs. **The split is the point:** reminders (things that arrive unprompted and need doing) are recorded durably; action confirmations ("Expense added", "IOU added") stay pure toasts and must NOT be pushed here. Ids are day-scoped (`owe-rakesh-2026-07-27`) so a nudge can't stack on remount but can legitimately reappear tomorrow.

**Entries are CLAIMS, not log lines — `reconcileNotifications` keeps them true.** An effect (placed after the `budgetStatus` memo so it reuses that derivation) recomputes what's outstanding from `buildReminders` + live budget/sync checks on every data change, then **drops** entries whose cause is gone (bill paid, person settled) and **rewrites** ones still true but changed (₹300 → ₹60 after a partial settle). Pruning alone isn't enough: a surviving entry quoting money you've already paid is the exact bug this whole area started with. Read state survives a rewrite — re-flagging unread would nag you about your own payment. Only `DERIVED_KINDS` (bill/iou/budget/sync) are touched; goal/streak/info are events and never auto-removed. Day-scoping plus reconcile also caps growth: yesterday's copy is never in today's live set.

Rows are tappable — `meta.go` routes to the IOU wallet (with `focusPerson` deep-linking straight to that person), the dashboard's due-bills list, budget settings, or Sync Status. The bell lives in the dashboard header only, so the **Home nav item carries an unread dot** from every other tab. Opening the sheet marks everything read; rows dismiss individually, "Clear all" empties it. Guarded by `notifications.test.js` + e2e `15-notifications.spec.js`.

Streak iconography is **PawPrint** (the trail the lion mascot leaves — echoes the terrain hero's "ground ahead" language) and **Shield** for the forgiveness credits, which are labelled **"shields"** in the UI. `streak.js` keeps its internal `freezesHeld` / `frozenDays` / `"frozen"` vocabulary — only the user-facing copy changed. Don't go back to flame + snowflake; that pairing was rejected as generic.

Toasts themselves are anchored to the **top** (`24px + env(safe-area-inset-top)`), sliding down into view. A bottom anchor was tried and reverted — the user found it awkward. The wrapper stays `pointerEvents: "none"` (only the pills are tappable) so a top toast never blocks the form beneath it.

### Push notifications (Web Push + ntfy)
Bill/IOU reminders as real phone push, two channels behind one Settings → "Push Notifications" card:

**Web Push (primary, "real app" channel):** browser-native push via VAPID — notifications land in the device shade under NOMAD's name/icon, no extra app. `src/webpush.js` (tests `src/__tests__/webpush.test.js`) handles permission + `PushManager` subscribe using the VAPID public key from `GET /api/push` (cached in localStorage `nomad-vapid-key`, auto-refetch on stale-key subscribe failure). Subscriptions are stored in the user's own Supabase `push_subscriptions` table (endpoint PK, JSONB body); "Enable on this device" also upserts `notification_prefs` (dedupe stamp lives there) and registers in `user_registry`. `public/sw.js` has the `push`/`notificationclick` handlers (payload `{title, body, tag, url}`). Server side: `api/push.ts` (GET public key / POST canned test push — content fixed server-side so it can't be a spam relay; 404/410 → 410 expired) and `api/_webpush.ts` (`sendToSubscriptions` fans the daily digest out, returns expired endpoints which the cron prunes). **Owner env (only setup): `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`** — generate via `npx web-push generate-vapid-keys`. iOS needs Add-to-Home-Screen (16.4+); the UI explains when `PushManager` is absent. Tests: `api/__tests__/webpush.test.ts`, `api/__tests__/push.test.ts`.

**ntfy (optional alternative):** via the ntfy app (`src/ntfy.js`, tests `src/__tests__/ntfy.test.js`). Browser POSTs straight to the ntfy server (ntfy.sh is CORS-whitelisted in `vercel.json` CSP `connect-src`; custom servers must be added there). Config in localStorage `nomad-ntfy-v1` + `notification_prefs` row.

**Shared plumbing:** the `send-reports` cron builds ONE due-bill digest per user (`api/_notify.ts` `buildBillDigest`) and fans it out to whichever channels are on, deduped once per IST day via `notification_prefs.last_run_date` (upserted, so it works even when only web push is on). Client-side legs fire while a tab is open: the `App.jsx` bill-reminders effect mirrors `checkBillReminders()` output to `publishNtfy` AND to `registration.showNotification` (works in local-only mode, no server). `api/_notify.ts` is a hand-port of `financeUtils.js` recurring-due math (api/ is CommonJS, can't import ESM `src/`) — change both together; guarded by `api/__tests__/notify.test.ts`.

## Key conventions / gotchas

- **`COLS` (`dbCols.js`) is the only source of truth for column lists.** Never inline a column array in a `toSB()` call — add the field to `COLS.<table>` once and every write path picks it up. `dbCols.test.js` guards required fields. A field written *only* through a partial upsert (`sbUpsert("splits", [{id, settled, skipped}], …)`) still needs to be in `COLS` — the full-row paths (first-connect migration, `heal()`, undo-restore) go through `toSB` and silently drop anything missing, so the row re-inserts with the column's DB default. That's how `skipped` used to lose every write-off.
- **IDs are client-side:** `uid()` (App.jsx) prefers `crypto.randomUUID()`, base36 fallback. No server IDs.
- **All amounts stored in INR (₹).** Foreign input converts at entry time; original currency + rate kept in `nomad-currency-meta` keyed by tx id.
- **`receiptUpload.js` 3 modes:** signed (`cloudName`+`apiKey`+`apiSecret`, SHA-1 via Web Crypto) → unsigned (`cloudName`+`uploadPreset`) → local (no `cloudName` → compressed data URL). `isLocalReceipt(url)` = `url.startsWith("data:")`.
- **Startup is stale-while-revalidate:** `load()` paints from `nomad-v5` then refreshes from Supabase async. Never `await sbGet(...)` before the first render.
- **Wallets/categories/sources are user-editable**, stored in localStorage state (`WALLETS`/`DC`/`DI`/`RC` are just default seeds). `wallets` state is the live source — never hardcode `{upi_lite,bank,cash}`.
- **Group splits use `distributeAmount` (`grpShareMap`)**, not `total/n`, to avoid ₹0.01 residue. `addE` must include `paidBy` in its `COLS.expenses` write or group summaries break on reload.
- **Tags were removed** — don't re-add (redundant with Events). SQL `tags` columns are dead but harmless.
- **Routine date math** uses a noon anchor (`new Date(y, m, d, 12)`) to dodge DST off-by-one. Keep it when touching streak/calendar code.
- **History search goes through `txSearch.js` — and AMOUNTS are searchable.** The original inline filter matched note / category / source / split / event names only, so typing `105` returned "0 results" with a ₹105 row on the calendar directly above the box. Rules live in the module so the UI can state them: tokens are whitespace-split and **ANDed** (`curd 105` = that row only, order-independent), each token matches a text field **or** the amount, whole-rupee tokens match to the **nearest rupee** (`105` → ₹105 / ₹105.40 / ₹104.60) and **never as a digit substring** (`105` must not find ₹1,050 — that turns every search into noise). Searching deliberately **ignores the month chip** and spans every month; the count line says so. The `Filter` badge counts only the **hidden** filters — including the visible search box in that count made "Filter 1" light up for a plain search and read as "something you can't see is suppressing your results". Guarded by `txSearch.test.js` + e2e `18-amount-search-and-hero.spec.js`.
- **`txParsers.js` is the only source for amount/voice/CSV parsing.** `parseAmount` handles EU comma-decimal, US thousands, and Indian lakh formats. `parseBankCsv` handles HDFC/ICICI/SBI and generic CSV layouts with auto-detected column headers (no row-count cap). Don't re-implement these inline in `App.jsx`.
- **Haptics are delegated globally — never wire them per-button.** `attachGlobalHaptics()` (haptics.js, installed once in `main.jsx`) ticks on every interactive tap via one capture-phase click listener (buttons, links, `role=button`, and any `cursor: pointer` element). Adding `hapticSelection()` inside a new onClick is redundant (same-gesture dedupe swallows it), and per-button wiring is exactly the bug this replaced — surfaces that forgot the call felt like "haptics randomly broken". Outcome haptics (`hapticSuccess`/`hapticError` via toasts, `hapticMedium` for deletes) stay explicit and always fire. Routine.jsx's local `haptic()` must keep routing through the shared module, never `navigator.vibrate` directly. Guarded by `haptics.test.js`.
- **Any AI mode that returns an ARRAY needs a raised `maxTokens`.** The 1024 default truncates a long grocery receipt / 60-row statement mid-array, and truncated JSON is unparseable — which surfaced to the user as "AI returned non-JSON response". `LIST_MODE_MAX_TOKENS` in `food-vision.ts` covers `receipt-items` / `statement` / `ledger`; `extractJSON` (`_ai-provider.ts`) is the backstop, salvaging complete elements from a truncated array via `repairTruncatedJSON` (which returns `null` — and so rethrows — when the brackets are already balanced, i.e. genuinely malformed rather than cut off).
- **The omnibus `ai-analyze.ts` is the preferred pattern for new AI features** — add a mode there rather than a new file, to stay under the Vercel Hobby function limit.
- **Semantic color tokens** (`--pos`, `--neg`, `--danger`, `--acc`, `--acc2`, `--warn`, `--gold`) live in the theme maps in `App.jsx`; use them for any new UI color instead of raw hex. Raw hex remains ONLY where var() can't go: 8-digit hex+alpha literals, values fed to `alpha()` or `${x}NN` string concat (`tc`, `acc/grn/ind/gld`), `<input type="color">` state, category/wallet seed data, and the theme maps themselves.
- **NEVER hand-roll a colour tint — use `src/tint.js`.** `withAlpha(c, 0.13)` for a decimal opacity, `tint(c, "22")` for the `color + "22"` hex-suffix idiom. Both keep the byte-identical old output for 6-digit hex and route everything else through `color-mix`. **This is not a style rule, it's a bug class:** category, wallet and income-source colours are user-editable AND several seeds are CSS vars — `DC.coffee` = `var(--warn)`, `DC.rent` = `var(--acc2)`, `WALLETS.cash` = `var(--warn)`, Routine's "Light" sleep quality = `var(--amber)`. Hex-only tinting broke those two ways, both silent: (a) a hex PARSER (`parseInt(hex.slice(0,2),16) || 0`) yields NaN → `|| 0` → `rgba(0,0,0,a)`, i.e. translucent BLACK that reads as a deliberate dark chip — this is what made the quick-add Coffee chip and the whole "Split with friends" panel look wrong; (b) the SUFFIX form yields `var(--warn)24`, which is not a colour, so the browser drops the declaration and you get NO tint — the Cash wallet tile's icon chip had neither a fill nor its dashed ring while Bank and UPI Lite had both. `alpha` inside the Add-form render is just an alias for `withAlpha`, and `trendHexA` delegates too. Module constants (`MINT`/`CORAL`/`AMBER`/`VIOLET` in IOUWallet, `ACCENT`/`GROUP_COLORS` in NomadLite, `acc/grn/ind/gld`/`tc` in App) are hex by construction and safe either way. `lum()`/`ink()` in IOUWallet hex-parse too: every caller passes hex today, and `lum` now returns a mid-grey for non-hex so a future `ink(c.color)` can't silently pick unreadable light-on-light text. Guarded by `tint.test.js` + e2e `18-amount-search-and-hero.spec.js` (asserts the Cash tile is tinted and dashed exactly like the hex wallets, and that no var-coloured chip surface resolves to black).
- **`api/ai-analyze.ts` has a sanitize step** — after AI returns JSON, each mode's `sanitize()` function normalises enum values and resets out-of-list IDs to `null`. Always add sanitization when accepting AI output for a new mode; don't let raw AI strings reach the client.
- **`balances.test.js` and `helpers.test.js` mirror inline logic in `App.jsx`** — they duplicate and test pure functions that live inside the monolith. If you extract or change `wBal` accumulation or `parseAmount`/`isUpiLite`, update these tests to match.
- **The dashboard hero is the "terrain" layout** (`TerrainHero` in App.jsx): 30-day total-balance trail as layered SVG contour bands hanging from the TOP edge (inverted ridgeline — higher balance reaches deeper; axis labels ride the ceiling), with the "Where you stand" readout centered in the open ground beneath it, burn-rate runway, In/Out/Kept triad, and frosted-glass wallet "cache" tiles (near-clear neutral glass; a low terrain silhouette in the wallet color rises from the tile floor with height = that wallet's share of total money, 7-day trend badge top-right via the `wWeek` memo — which mirrors `wBal`'s accumulation rules, change together; 3 per row, wrapping — tap = reconcile, cash keeps its ⟳ recount). **Tile spacing is deliberately tight (~135px tall, was ~180 for the same four short lines)** — the dead bands were an 11px margin under a 28px icon chip and a 9+7px gap above the status rule. If you shorten the tile further, scale the silhouette's pixel `height` with it: its `0 0 100 60` viewBox math is share-driven and unchanged, so only the px height controls what fraction of the tile it covers, and it must stay ≈⅓ or a high-share wallet's fill climbs behind the balance. e2e `18-amount-search-and-hero.spec.js` pins the tile height, the icon gap, and that silhouette ratio. Series/burn math lives in `financeUtils.js` (`balanceTrail`, `runwayInfo`); the `terrainData` memo in App.jsx builds the signed deltas and MUST mirror `wBal`'s accumulation rules — change them together. Hero numerals use `--font-m` (Martian Mono, loaded in the same @import as the other fonts); all hero colors are theme vars so dark mode works. Don't reintroduce a "Total Balance" card — e2e `01-local-mode` asserts the hero's "Where you stand" readout. **The chart is FULL-BLEED and must stay that way:** its wrapper carries `marginLeft/Right: -16` to escape the page column's padding, so the fill reaches the real screen corners (the root's `overflow-x: clip` stops the bleed becoming page scroll). Geometry constants in one place at the top of `TerrainHero` — `W` (viewBox width), `DOT` (where data ends, so the today marker stays whole at the edge), `TOP`/`SPAN` (ridgeline band; keep `TOP + SPAN ≲ 155` or the trail collides with the readout). The level stretch from `DOT` to `W` is intentional and short, and it sits exactly on the dashed today-pin. Extrapolating the last segment's slope out to the edge instead was tried and reverted — it draws the trail past its own pin line, i.e. implies data after today. The complaints this fixed were all "the graph feels flat": 16px dead gutters down both sides, a ~5% flat strip at the right (data used to stop at x=410 with a `L430,lastY` bar), and a thick always-solid slab above the ridgeline (`TOP` was 40).
  **Three things make the terrain read as smooth rather than sharp — don't undo any of them:**
  1. **`monotonePathD`** (financeUtils), not Catmull-Rom. Catmull-Rom takes each tangent from the point's *neighbours* (`(next − prev)/6`), which is non-zero and asymmetric at a one-day spike, so every reversal drew a hard corner AND the curve overshot the data. Monotone (Fritsch–Carlson) forces the tangent to **zero at each local extremum** — peaks become rounded crests — and provably never overshoots.
  2. **`smoothSeries(bals, 2)`** eases the DRAWN series (endpoints pinned). Monotone alone turned a ledger with a few big spend days into flat shelves joined by near-vertical cliffs, which still reads as sharp. Two `[1,2,1]/4` passes leave a lone spike at ~37% and don't touch multi-day trends. **This affects the curve only** — today's balance, the 30-day delta, In/Out/Kept and the burn rate all come from raw values, and the pin/marker land on the exact (pinned) endpoint.
  3. **The fill is a vertical gradient** (`#nmTerrainFill`, `userSpaceOnUse` so every lifted band fades on the same axis) going transparent at the ceiling → opaque at the ridgeline. Flat `fillOpacity` is what made the area above the trail a uniform slab with a straight cut and square corners across the top. `#nmContour` / `#nmPinFade` do the same left-to-right for the contour edges and the today-pin so they emerge instead of ruling the full width.
  **The axis labels ("30 days back" / "today") live INSIDE the chart**, absolutely positioned at its top corners — the gradient is near-transparent up there, so they stay legible. They used to occupy their own row above the graph, which pushed the terrain down and put a line of text right where the fill was cut off. `TOP` reserves their headroom. Guarded by e2e `18-amount-search-and-hero.spec.js` (full-bleed width, corner-closing fill, gradient stops, labels-inside, flat-run-out cap).
- **Single-source decision helpers live in `financeUtils.js` — don't re-inline them.** A recurring bug class here was the same decision copied into several call sites then drifting apart (e.g. recurring category looked up in expense `cats` in one place but `RC`/`recCats` in another; the UPI-Lite ₹5000 ceiling enforced on calibration/income but not transfers; the settle modal defaulting a *receive* to UPI-Lite which the save then rejects). These now have one tested home: `resolveRecCategory` (every recurring-category render), `exceedsUpiLiteBalance`/`UPI_LITE_MAX_BALANCE` (every path that credits UPI Lite), `defaultSettleWalletId` (settle/record-payment default wallet). Call them; don't paste a fresh copy. Guarded by `guards.test.js`.
